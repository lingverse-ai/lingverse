# 写初稿

## 0. 开写前
- 读作者档案、口吻档案，以及 moling-structure-and-opening 的输出：材料清单、骨架、选定的开头、收藏件和福利。
- **目标篇幅**：先按材料估算：每条材料约 120～150 字，乘以条数，开写前把这个预计篇幅告诉主人。主人另有要求按主人的；不答就按估算，并参考文章类型——复盘型、方法型 1500～2500 字；观点型 1000～1500 字；资源合集按条目定。素材少就写短，不注水。
- 这一步只写**母版**，不分平台。平台版本交给 moling-multi-platform。

## 1. 能用的材料（只有这些）
- 作者档案里的真事素材库。
- 主人的样稿原文（口吻档案的证据片段）。
- 主人在这次对话里亲口说的话。
- 有出处的【推算】：写出算式，等主人确认。

**不能用**：口吻学习时的试写；别人的故事；行业里的「一般来说」；为了让段落圆满补出来的动作、心情和小数字（几天、几次、几个人）。

## 2. 写法
1. 开头用选定的那个，原样放上，不重写。
2. 按骨架逐节写。每节写三样：观点（一句）、材料（标出处）、读者能做的一个动作。
3. 某一节的材料不够：
   - 写一个短段，只放有出处的部分；
   - 在缺口处标 `【问：具体问题】`，比如「【问：订了不来拿的，你后来怎么处理的？】」；
   - 骨架里标了「待问，未答不写」的整节，主人没答就**不写这一节**。
4. 节奏按口吻档案：句长、段长、自称、标点、口头禅的频率和位置。
5. 收藏件放在骨架规定的位置。表格里填的是主人的真实情况；不知道的格子留空，或者标「示例」。
6. 福利放在文末，交付方式先写母版版本，平台差异留给多平台改写。
7. 结尾落在一个动作、一个数字或一句主人的话上。

## 真实感与共鸣（爆款的底子）
墨灵的主人多是需要流量的项目操盘手和自媒体创业者，读者也是。让人觉得「这说的就是我」，靠的是这四样，都只能用主人给过的料：
- **踩过的坑**：错在哪一步，当时损失了什么。
- **算过的账**：钱、时间、数量，写出算式。
- **当时怎么想的**：做决定那一刻的念头，包括想错的。
- **读者的处境**：写出读者此刻正卡在哪，用他会说的话。
具体场景压过抽象道理：写「周二下午花桶快空了」，不写「供需失衡」。料不够就问主人，不编。

## 3. 写完自查（交出去之前）
- 每一句里的事实，都能指出出处吗？不能就删，或者改成【问】。
- 篇幅和目标差多少？超出 30% 先删重复的例子；不够也不要补，直接告诉主人「材料只够这么长」。
- 收藏件、福利都在吗？
- 骨架里每一节都写了吗？跳过的写明原因（待问）。

## 4. 输出
```
初稿（母版）｜目标 N 字｜实际约 M 字
正文…
出处表：句子 → 素材第 N 条 / 样稿 N / 本次对话
待问：【问】…（N 处）
跳过的节：…（原因）
```
最后说一句：「我先拿去深改」，然后按 moling-de-ai-edit 的深改档继续，不问平台。待问很多（3 处以上）时，先问主人，答完再改。
