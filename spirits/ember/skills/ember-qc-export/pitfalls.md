# 19 坑清单与平台规格

## 1. 19 个坑（v11 实测，按出现顺序）→ 逐条检查
| # | 坑 | 怎么查 | 解法 |
|---|---|---|---|
| 1 | 人是静止照片，不「活」 | 联系表同一镜头 5 帧几乎一样 | 换图生视频；提示词加眨眼、呼吸、转头 |
| 2 | 镜头重复 | project.json 里 src 有重复 | 每个素材只用一次 |
| 3 | 各条素材色调不一 | 联系表一眼看色温跳 | 统一调色，再整体加同一层颗粒 |
| 4 | AI 视频乱出 logo / 字 | 逐格看背景、道具、衣服 | 裁掉、遮掉，或换素材 |
| 5 | 对口型难看 | 画面里有唱歌的嘴 | 不对口型，说唱只放音频 |
| 6 | 字体风格跑偏（细体、窄体、怪颜色） | 看字重和颜色是否和上一版一致 | 修改单写死字体文件和颜色值 |
| 7 | 歌太短、结构不完整 | 听：有没有铺垫 → 高潮 → 结尾 | 在重拍上重新剪歌，30ms 交叉淡化 |
| 8 | 不该说话的镜头叹气、嘴动 | 逐格看嘴 | 只用干净的那几秒（src_start + 缩短） |
| 9 | 配饰消失 / 出画 | 每个镜头都找必带配饰 | 删整条或换片段；锁定清单写 in EVERY shot |
| 10 | 结尾段像幻灯片 | 最后几刀都慢、都静 | 每个重拍、重音都切；只用运动中的片段 |
| 11 | 3 秒后脸和眼镜变形 | 看每条 3 秒以后的帧 | 只用前 2.5 秒 |
| 12 | 短裤变长裤（下装跑偏） | 每个全身镜头看下装 | 重做；锁定清单写 never long pants |
| 13 | 翻滚镜头倒置后配饰看不见 | 看桶滚镜头的中段 | 调整 src_start 取配饰可见的那段 |
| 14 | 一个词跨两刀、混入另一种语言 | words 的 until 超过镜头 out；文字有非 ASCII | 一刀一个词；只用一种语言，渲染后检查 |
| 15 | 素材少、同一动作反复出现 | 9 个素材切 26 刀这种 | 补拍新场景；先粗剪定顺序 |
| 16 | 走路像平推、没迈步 | 看脚离不离地 | 重新生成，写 real walking steps |
| 17 | 坐着像假人 | 看有没有眨眼、转头 | 重新生成「活」的版本 |
| 18 | AI 皮肤太光滑 | 1:1 看脸 | 加细颗粒、轻锐化；不磨皮、不加雀斑 |
| 19 | 文字太静，不跟音乐 | 逐帧看字进场时间 | 每个词踩拍进场：闪帧 + 缩放冲击 + 滚动 + drop 故障 |

可自动查的（复制运行）：
```bash
python3 - <<'PY'
import json,collections
p=json.load(open('project.json')); S=p['shots']
print('2 重复素材:', [k for k,v in collections.Counter(s['src'] for s in S if s['src'] not in ('INTRO_CARD',) and not s['src'].startswith('color:')).items() if v>1])
cuts=[s['in'] for s in S]+[p['duration']]
bad=[w['text'] for w in p.get('words',[]) if any(w['t']<c<w.get('until',w['t']+.5)-1e-3 for c in cuts)]
print('14 跨刀的词:', bad)
print('14 非 ASCII 的词:', [w['text'] for w in p.get('words',[]) if not w['text'].isascii()])
b=json.load(open('beatmap.json')); T=b['beats']
print('19 不在拍上进场的词:', [w['text'] for w in p.get('words',[]) if min(abs(w['t']-t) for t in T+[0])>0.05])
PY
```
（要求全中文字幕时，忽略「非 ASCII」那一行。）

## 2. 平台规格
| 平台 | 画幅 | 分辨率 | 时长建议 | 画面安全区 | 链接 / 导流 |
|---|---|---|---|---|---|
| 抖音 | 9:16 | 1080×1920 | 15～60s | 底部约 1/5、右侧约 1/8 不放字 | 画面和文案都**不放** |
| 小红书 | 9:16（或 3:4） | 1080×1920 | 15～60s | 底部 15%～20% 可能被挡 | **不放** |
| 微博 | 9:16 或 16:9 | 1080p | ≤60s | 底部留白 | **不放** |
| X | 16:9 | 1920×1080（可传 4K） | ≤2:20 | 无 | 帖子里可放，画面里不放 |
| 公众号视频 | 16:9 | 1920×1080 | 不限 | 无 | 画面不放二维码，引导写在文章里 |
通用：H.264、yuv420p、30fps、AAC、-14 LUFS 左右；封面单独导出。

## 3. 发布前提醒（交付时逐条告诉主人）
- 发布由主人点，流萤不发。

## 4. 新增坑（流程层面）
- 拍点只信一个 BPM → 歌里有变速/切段就漂；剪过的歌一定重跑 beatmap，并用耳朵复核重拍。
- 歌词时间靠猜 → 大字早半拍或晚半拍最显业余；用 lyrics_align.py，文字以主人为准。
- 直接出整片才给主人看 → 一改就是全片重渲；先出 --excerpt 片段。
- 等渲染时一直不说话 → 主人以为卡死；后台跑 + 「好了说继续」。
- 换对话后从头问 → 先看 state.py status 和 DECISIONS.md。
- 人不像就逐帧修 → 改 LOCK 文字或参考图，从源头重出。
- 闪帧太密 → 光敏风险，1 秒最多 3 次。
